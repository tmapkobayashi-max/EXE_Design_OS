# 提案資料のつくり方 ― 手順書

作成：2026-07-23
対象：EXE MATE 社内
**社外秘。GitHubにも上げない。**（`exe-design-os` フォルダの外に置いてあるのはそのため）

---

## 0. これは何か

「〇〇の資料を作って」と頼めば、**毎回EXEのテイストで提案資料ができる仕組み**の使い方。

仕組みの本体は `exe-design-os` フォルダ（＝GitHubの `tmapkobayashi-max/exe-design-os`）にある。
そこに**色・寸法・図の描き方・守るべきルール**が全部書いてある。
AIにはデザインを「考えさせない」。ルールを渡して「組み立て」だけさせる。

できあがるもの：

- **deck.html** … ブラウザで開く資料。目次・前後ボタン・全画面・PDF保存つき
- **イラスト発注書.md** … 絵が必要な箇所の注文書
- **検証表.md** … AIの自己採点

---

## 1. 全体の流れ

```
   ① 案件の情報をそろえる
            ↓
   ② AIに作らせる（CodexかClaude）
            ↓
   ③ 画像で見て、直すところを指摘する   ← ここを2〜3周まわす
            ↓
   ④ （必要なら）イラストを発注して差し込む
            ↓
   ⑤ ブラウザで「PDFで保存」→ 納品
```

**③を飛ばさないこと。** AIは一発では仕上げない。2〜3周まわす前提で時間を見ておく。

## 3. 案件の情報をそろえる（①）

`exe-design-os\prompts\01_資料をつくる.md` の末尾にある【案件】欄を埋める。

```
顧客名：
案件名：
現状の困りごと：
EXEの必殺技：
枚数の目安：
補足：
```

**「現状の困りごと」と「EXEの必殺技」が資料の芯**になる。ここが薄いと何周まわしても良くならない。
既存の企画書やPDFがあるなら、先にClaudeに読ませて要約させるとよい。

**補足欄に必ず書くこと**

- 未確定の数字（金額・スケジュール）は「未定」と明記する。**AIに数字を作らせない**
- 使ってはいけない話題（他案件の内容、裏取りできていない実績など）
- 実機デモの有無

## 4. AIに作らせる（②）

### パターンA：Codexを使う（松浦社長のアカウント）

1. `exe-design-os.zip` を用意する（下の「ZIPの作り直し」参照）
2. Codexの新しいタスクを開き、**ZIPを添付**する
3. `prompts\01_資料をつくる.md` の中身をコピーして貼り、【案件】欄を埋めて送信

**GitHubのURLを渡すだけでは動かないことがある。**
Codexの実行環境が外部ネットワークに出られない場合、
`SEC_E_NO_CREDENTIALS` などのエラーで止まる。**ZIP添付が確実。**

### パターンB：Claudeを使う

`EXE提案資料テンプレ` フォルダでチャットを始める。
`CLAUDE.md` が自動で読まれるので、説明なしで「〇〇の資料を作って」と頼める。

**Claudeの利点：**

- **スクリーンショットで自分の出力を見て直せる**（Codexにはできない）
- ローカルのファイルを直接編集できる
- GitHubの中身を読める

**Claudeの制約：**

- **画像（イラスト）を生成できない**

### どちらを使うか

| 状況 | 使うもの |
|---|---|
| ゼロから1本作る | どちらでも可 |
| できた資料を直す | **Claude**（画像で確認しながら直せる） |
| イラストが欲しい | **ChatGPTの画像生成**（下記） |

## 5. 画像で見て、直す（③）★ここが肝

**ブラウザで見るだけでは不十分。1枚ずつ画像に書き出して確認する。**

`deck.html` には検査モードが入っている。URLの末尾に `?p=7` を付けると7枚目だけが原寸で出る。

### Claudeに頼む場合

「全ページを画像で確認して、破綻がないか報告して」と言えばやる。
（内部でEdgeのヘッドレスを使ってPNG化している）

### 自分で確認する場合

ブラウザで `deck.html` を開き、下のバーの「PDFで保存」でPDF化してから通しで見る。

### よく出る不具合と、直させ方

| 症状 | 言い方 |
|---|---|
| 画面がスカスカ | 「◯枚目、上下が空きすぎ。図を大きくして枠いっぱいに」 |
| 文字が図からはみ出す | 「◯枚目、円が小さい。文字幅＋80px以上の直径に」 |
| 見出しが変なところで折れる | 「◯枚目の見出しに `<br>` を入れて改行位置を指定して」 |
| 絵が内容と合っていない | 「◯枚目、〇〇を描いて。抽象的な図形で代用しないで」 |
| 意味なく色が違う | 「◯枚目、色を変える理由がないなら統一して」 |
| 円環がつながって見えない | 「◯枚目、円が大きすぎてリングを隠している。円を小さく、リングを大きく」 |

### 直させるときの鉄則

**1回のお願いで1か所だけ。** まとめて頼むと他が崩れる。

```
7枚目だけ直してください。他のスライド・CSSは一切変更しないでください。
・（直すことを箇条書きで）
・それ以外は現状維持。修正後の該当スライドのHTMLのみ出力
```

## 6. イラストを入れる（④）

**絵がなくても資料は成立する。** まず骨格を作って社内で合意し、それから絵を足すほうが速い。

### 手順

1. AIが出した `イラスト発注書.md` を開く
2. 先頭の「共通指定」をコピーしておく
3. **ChatGPTのチャット画面**（Codexではない）を開き、
   「構図」＋「共通指定」を貼って送る
4. 届いたPNGを `案件フォルダ\sozai\illust\` に、発注書の指定ファイル名で保存
5. AIに「画像が揃ったので差し込んで」と伝える

### 絶対に守ること

- **1チャットで1画像。** まとめて頼まない
- **絵柄をそろえるため、2枚目以降は同じチャットの続きで頼む。** チャットを分けるとズレる
- **画像に文字を入れさせない。** 日本語は崩れるし、あとから直せない。文字はHTML側で重ねる

### 届いたPNGの確認

- 文字・数字が入っていないか（**いちばん守られない**）
- ピンク以外の派手な色が入っていないか
- 前の絵とトーンが揃っているか
- 文字を載せる予定の側が空いているか

NGなら**同じチャットで**「文字が入ってしまったので消して」と続ける。作り直すより速い。

## 7. 納品する（⑤）

1. ブラウザで `deck.html` を開く
2. 下のバーの **「PDFで保存」**
3. 印刷ダイアログで「送信先＝PDFに保存」、**余白なし・背景のグラフィック オン**
4. 保存

**HTMLのまま渡す場合**：`deck.html` 1ファイルで完結している（画像を差し込んだ場合はそのフォルダごと）。

**パワポが必要な場合**：HTMLからの自動変換はできない。
`exe-design-os\assets\pptx-guide.md` の方式で別に作ることになる。要相談。

## 8. 仕組み側を直す（重要）

**AIが同じ失敗を繰り返すのは、たいてい「ルールに書いていないから」。**

その場で直させるだけでなく、`exe-design-os\docs\07_ART_DIRECTION.md` にルールを足す。
そうすれば次の案件から自動的に守られる。

これはClaudeに頼めばやる。「この失敗が繰り返されないようルールに足して」と言えばよい。

### 変えたら必ずやること

1. `SOURCE_OF_TRUTH.md` を先に直す
2. 影響するファイルを**全部**洗い出してから直す（例示・表・見本まで）
3. `examples\` の見本も直す。**見本が古いままだとAIは古いほうを真似る**

## 9. GitHubの更新

**Claudeはアップロード（push）ができない。** 手作業で上げる。

1. https://github.com/tmapkobayashi-max/exe-design-os を開く
2. **上げたいファイルが入るフォルダを先にクリックして中に入る**（←ここが肝）
3. `Add file` → `Upload files` → ドラッグ → `Commit changes`

**フォルダに入らずにアップすると、リポジトリ直下に置かれて重複する。**
過去に一度やらかしている。直下に古い版と新しい版が並ぶと、AIがどちらを読むか不定になる。

フォルダごとまとめて上げるときは、フォルダ自体をドラッグすれば階層は保たれる。
**`.git` フォルダは絶対に入れない。**

### ZIPの作り直し（Codexに渡す用）

ルールを変えたらZIPも作り直す。Claudeに「ZIPを作り直して」と言えばやる。

## 10. 困ったとき

| 症状 | 対処 |
|---|---|
| AIが青い資料を作ってくる | `docs\07_ART_DIRECTION.md` が古い。ZIP/GitHubを更新する |
| Codexが「読めない」と止まる | ZIPを添付する。URLだけでは届かないことがある |
| 何度言っても直らない | 1回1か所に絞る。まとめて頼まない |
| どのファイルが正しいか分からない | `SOURCE_OF_TRUTH.md` を見る |
| 資料が全体的に地味・スカスカ | 図を大きくする。要素を足すのではなく既存の要素を拡大する |

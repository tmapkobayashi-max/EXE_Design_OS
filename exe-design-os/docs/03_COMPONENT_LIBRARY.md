# EXE Design OS - 03 Component Library

Version: 1.0

---

# Purpose

The Component Library defines the standard building blocks used in every EXE proposal.

Components exist to create consistency, improve readability, and reduce unnecessary design decisions.

Whenever an official component exists, it must be used instead of creating a custom layout.

---

# Component Selection Priority

When selecting a component, always follow this order.

1. Best communicates the message
2. Simplest structure
3. Highest readability
4. Matches existing EXE components
5. Consistent throughout the proposal

---

# Component Catalog

| Component | Purpose | Best Use | Avoid |
|-----------|----------|----------|-------|
| Hero | First impression | Cover page, proposal summary | Detailed explanations |
| Compare | Compare two states | Before / After, Current vs Future | Timelines |
| Flow | Explain a process | Workflow, migration steps | KPI presentation |
| Timeline | Chronological information | Schedule, roadmap | Feature comparison |
| Numbers | Highlight important metrics | Achievements, KPI, Results | Procedures |
| Cards | Multiple independent items | Features, Services, Benefits | Sequential processes |
| Relationship | Show connections | System architecture, relationships | Time-based explanations |
| Hierarchy | Parent-child structure | Organization, system layers | Comparisons |
| Cycle | Repeating process | Continuous improvement, PDCA | Linear workflows |
| Matrix | Two-axis comparison | Priority analysis, evaluation | Simple lists |

# Component Rules

## Hero

Purpose

Capture attention.

Communicate the proposal theme immediately.

Contains

- Proposal title
- Subtitle
- One supporting visual
- One key message

Never overload the Hero component.

---

## Compare

Purpose

Help clients understand change.

Standard Layout

Current State

↓

Future State

Use Sub Grey for the current state.

Use EXE Pink for the future state.

Limit comparisons to one primary theme.

---

## Flow

Purpose

Explain sequential actions.

Use arrows.

Keep direction consistent.

Maximum

7 steps.

If more than 7 steps,

split into multiple flows.

---

## Timeline

Purpose

Explain time.

Use chronological order.

Always include clear milestones.

Avoid unnecessary detail.

---

## Numbers

Purpose

Create impact through data.

Rules

Level 1 typography.

Largest element on the slide.

Use EXE Pink.

Support with a short explanation.

Never display too many KPIs.

Recommended

1–4 numbers.

---

## Cards

Purpose

Present multiple independent ideas.

Recommended

3–6 cards.

Every card should have

- Icon
- Title
- Description

Cards must have equal size.

---

## Relationship

Purpose

Explain connections.

Use simple connecting lines.

Avoid crossing lines.

Keep hierarchy visually clear.

---

## Hierarchy

Purpose

Explain structure.

Always start from the highest level.

Expand downward.

Avoid excessive branching.

---

## Cycle

Purpose

Represent continuous improvement.

Use circular layouts.

Recommended

4–6 stages.

Maintain clockwise direction.

---

## Matrix

Purpose

Compare information across two dimensions.

Limit to

2 × 2

or

3 × 3.

Avoid overly complex matrices.

---

# Component Combination Rules

Recommended combinations

Hero

↓

Compare

↓

Flow

↓

Numbers

↓

Timeline

This is the default proposal narrative.

Avoid placing multiple large components on the same slide.

One primary component per slide.

---

# Component Anti-patterns

Never use more than one primary component on a slide.

Never mix unrelated layouts.

Never use decorative diagrams.

Never create custom layouts when a standard component exists.

Never overload diagrams with text.

Never create flows with inconsistent direction.

Never compare more than two primary concepts in one Compare component.

---

# AI Decision Rules

When generating presentations,

always determine the message first.

Then select the component.

Never select a component based on appearance.

Select it based on communication purpose.

If multiple components are valid,

choose the simpler one.

If uncertainty remains,

follow this priority.

Compare

↓

Flow

↓

Cards

↓

Numbers

↓

Timeline

# Component Validation Checklist

Before output, verify:

✓ One primary component per slide

✓ Correct component selected

✓ Standard layout maintained

✓ No custom layouts

✓ Component supports the slide message

✓ Consistent spacing

✓ Consistent icon style

✓ Appropriate use of EXE colors

✓ Diagram easier to understand than text

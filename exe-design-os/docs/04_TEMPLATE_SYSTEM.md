# EXE Design OS - 04 Template System

Version: 1.0

---

# Purpose

The Template System defines the standard narrative structure for EXE proposals.

Templates exist to ensure every proposal follows a logical story rather than becoming a collection of unrelated slides.

Each proposal type should reuse existing templates whenever possible.

Never create a new template unless the narrative itself is fundamentally different.

---

# Narrative Principle

Every proposal tells a story.

The client should naturally progress through the following journey.

Current Situation

↓

Problems

↓

Future Vision

↓

Solution

↓

Benefits

↓

Implementation

↓

Trust

↓

Decision

Never explain the solution before explaining the client's problem.

---

# Standard Proposal Template

This is the default structure for most system proposals.

| Slide | Purpose | Component |
|--------|---------|-----------|
| Cover | Proposal overview | Hero |
| Background | Current situation | Compare |
| Issues | Problems | Compare |
| Solution | Proposed solution | Cards |
| Process | Implementation flow | Flow |
| Benefits | Expected improvements | Numbers |
| Schedule | Timeline | Timeline |
| Support | EXE strengths | Cards |
| Closing | Call to Action | Hero |

This template should be used unless another template is more appropriate.

---

# Proposal Categories

Every proposal belongs to one of the following categories.

| Proposal Type | Recommended Template |
|---------------|----------------------|
| System Development | Standard Proposal |
| Cloud Migration | Standard Proposal |
| DX Consulting | Standard Proposal |
| Website Renewal | Website Proposal |
| EC Site | EC Proposal |
| AI Introduction | AI Proposal |
| Maintenance | Renewal Proposal |
| Operation Support | Support Proposal |

Templates inherit the same design rules.

Only the narrative changes.

# Slide Rules

Each slide communicates one primary message.

Each slide should contain one primary component.

Text should remain within two to three lines whenever possible.

Prefer diagrams over paragraphs.

---

# Template Selection Rules

When generating a proposal,

identify the proposal category first.

Then choose the closest existing template.

Do not create a new template if an existing one communicates the same narrative.

---

# AI Decision Rules

Determine:

1. Proposal category

↓

2. Narrative structure

↓

3. Slide sequence

↓

4. Component selection

↓

5. Visual rules

Never reverse this order.

Never start with layout.

Always start with the story.

---

# Template Validation Checklist

Before generating a proposal, verify:

✓ Correct proposal category selected

✓ Appropriate narrative structure

✓ Logical story progression

✓ One message per slide

✓ Standard components used

✓ Consistent visual system

✓ Proposal ends with trust and decision

✓ No unnecessary slides

✓ No missing implementation plan

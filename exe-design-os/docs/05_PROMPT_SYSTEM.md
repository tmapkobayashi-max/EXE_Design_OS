# EXE Design OS - 05 Prompt System

Version: 1.0

---

# Purpose

The Prompt System defines how AI should think before generating any proposal.

It standardizes the decision-making process to ensure every proposal follows the same quality, structure, and design philosophy.

AI must follow this workflow before producing any output.

---

# Primary Objective

The objective is not to generate slides.

The objective is to generate proposals that are:

- Easy to understand
- Visually consistent
- Business-focused
- Trustworthy
- Ready for client presentation

Always prioritize understanding over information.

---

# Proposal Generation Workflow

AI must execute the following workflow in order.

Step 1

Understand the proposal request.

↓

Step 2

Identify the proposal category.

↓

Step 3

Determine the client’s problems.

↓

Step 4

Define the desired future state.

↓

Step 5

Select the appropriate proposal template.

↓

Step 6

Generate the slide sequence.

↓

Step 7

Select the correct component for each slide.

↓

Step 8

Apply the EXE Visual System.

↓

Step 9

Validate the proposal.

↓

Step 10

Generate the final output.

Never skip a step.

---

# Required Input

Before generating a proposal, AI should identify the following information.

Required

- Client Name
- Industry
- Proposal Theme
- Current Problems
- Proposed Solution

Recommended

- Target Audience
- Expected Benefits
- Project Duration
- Budget
- Existing Environment

Optional

- Competitors
- Existing Systems
- Risks
- Future Expansion

---

# Missing Information Rules

If required information is missing,

AI should make reasonable assumptions.

If assumptions may significantly affect the proposal,

AI should ask concise clarification questions before generating.

Never interrupt the workflow for minor details.

---

# Proposal Thinking Model

Every proposal should answer these questions.

1.

What is happening now?

↓

2.

Why is this a problem?

↓

3.

What future should be achieved?

↓

4.

How will EXE solve it?

↓

5.

Why is this solution valuable?

↓

6.

How will it be implemented?

↓

7.

Why should the client trust EXE?

↓

8.

What action should the client take?

---

# Slide Planning Rules

Each slide should have one objective.

Each slide should contain one primary component.

The narrative should naturally flow to the next slide.

Never duplicate information across slides.

---

# Text Generation Rules

Keep explanations concise.

Maximum

2–3 lines per text block.

Avoid technical jargon whenever possible.

Use plain business language.

Prefer active voice.

Every sentence should add value.

# Proposal Quality Checklist

Before generating the final proposal, verify:

✓ Client problem is clearly explained

✓ Future vision is clear

✓ Solution matches the problem

✓ Components are correctly selected

✓ Visual hierarchy is maintained

✓ Text follows the 2–3 line rule

✓ Proposal ends with trust and next action

---

# Repair Rules

If validation fails,

AI should repair the proposal before output.

Possible repairs include:

- Splitting overloaded slides
- Replacing text with diagrams
- Selecting a better component
- Improving visual hierarchy
- Shortening text
- Correcting color usage

Repeat validation until all critical checks pass.

---

# Output Requirements

Every proposal should include:

- Proposal title
- Slide sequence
- Component selection
- Text content
- Visual instructions
- Validation summary

Output should be suitable for HTML, Canva, PowerPoint, or PDF generation.

---

1. Consultant

✓ Correct template selected

✓ Components correctly chosen

# 提案資料を1本つくる（Codexへの依頼文）

これをCodexにそのまま貼り、最後の【案件】欄だけ書き換えて使う。

---

```
あなたはEXE MATE株式会社の提案資料をつくる担当です。
次のリポジトリを唯一の正典として、先に全部読んでから着手してください。

https://github.com/tmapkobayashi-max/exe-design-os

必ず読むファイル：
- docs/01_PHILOSOPHY.md 〜 06_VALIDATION_SYSTEM.md
- docs/07_ART_DIRECTION.md      ← 見た目の作り方。最重要
- templates/customer-proposal.md ほか、案件に合う型
- examples/ 配下の見本           ← 品質の基準。これに寄せる

■ 絶対に守ること
1. 色は docs/07_ART_DIRECTION.md に書かれたHEX以外を使わない。近い色で代用しない。
2. スライドは 1920×1080。外余白は104px以上。
3. レイアウトはCSS Gridで組む。position:absolute で文字を置かない（重なるため）。
4. 図の中に入れる文字は、HTMLで重ねずSVG内の<text>で置く。
5. 1スライド1メッセージ。本文は2〜3行以内。
6. 実績数字はページ内で最大サイズにする。
7. ノンブルは算用数字のみ。「Page:」等のラベルを付けない。
8. examples/ にある見本と同じ骨格・同じ部品を使う。新しいレイアウトを発明しない。

■ 特に守られにくい5点（docs/07_ART_DIRECTION.md 8-2〜8-5 に詳細）
9.  画面を埋める。上1/3・下1/3が空いたスライドは失敗。
    余白は「最低40px」であって「たくさん空ける」ではない。図は縦に伸ばして使う。
10. 図はスライドごとに作り分ける。同じ絵の使い回し・汎用の飾り図は禁止。
    図の線1本ごとに「これは何を表すか」を言えること。
    円環図は始点と終点を閉じ、要素を輪の外に出さない。
11. 色に意味を持たせる。ピンク＝自社・解決策・強調／Sub Grey＝現状・課題・他社。
    どちらでもないものの色を変えない（順番・月・工程を色分けしない。番号で示す）。
12. 見出しの改行位置は <br> で明示する。自動折り返しに任せない。
13. 図形の中の文字は図形からはみ出させない。円は文字幅＋80px以上の直径にする。
    長い語は円の外にラベルを置き、引き出し線でつなぐ。
14. 主題のモノを必ず描く。「大画面」の話なら画面を描く。建物と曲線だけの抽象図で
    代用しない。描いた要素すべてについて「これは何か」を言えること。
15. 循環図には回る向きの矢印を入れる。輪を閉じるだけでは足りない。
16. 全スライドの密度を揃える。1枚だけ詰まっていて他がスカスカ、にしない。
17. HTMLは改行とインデントを入れて出力する。1行に詰めない。
    スライドごとに <!-- ══ N. タイトル ══ --> のコメントを入れる。

■ 出力するもの（★3点セット。1つでも欠けたら未完成★）

【1】deck.html
　全スライドを1ファイルにまとめたHTML。
　目次・前後ボタン・全画面・PDF保存・?p=N の検査モードを含める。
　イラストが未入手の箇所は、後で画像に差し替えられるよう
　<div class="art" data-illust="ファイル名.png"> の形で枠を用意しておく。

【2】イラスト発注書.md
　★これを必ず一緒に出すこと。★
　templates/illustration-brief.md の書式に従い、
　この資料に必要なイラストを1枚ずつ、DALL-Eにそのまま投げられる文面で書き出す。
　・共通指定は先頭に1回だけ書く
　・各イラストは「構図」と「保存ファイル名」だけを列挙する
　・優先度A（必須）とB（あれば良い）に分ける
　・イラストが不要なスライド（表・数字が主役のもの）は、その旨を明記する

【3】検証表
　docs/06_VALIDATION_SYSTEM.md と docs/07_ART_DIRECTION.md のチェックリストに
　自分で回答した表。✅／❌ で答え、❌があれば直してから出す。

■ 案件
顧客名：
案件名：
現状の困りごと：
EXEの必殺技：
枚数の目安：
補足：
```

## 使い方の流れ

```
① 上の依頼文をCodexに投げる
        ↓
② deck.html ＋ イラスト発注書.md ＋ 検証表 が返る
        ↓
③ 発注書をChatGPT（画像生成）に1枚ずつ投げる  ※1チャット1画像
        ↓
④ 届いたPNGを sozai/illust/ に指定の名前で保存
        ↓
⑤ Codexに「画像が揃ったので deck.html に差し込んで」と伝える
        ↓
⑥ ブラウザで確認 →「PDFで保存」で納品物になる
```

イラストなしでも③〜⑤を飛ばせば資料として成立する。
まず骨格を作って社内で合意し、それから絵を足す順番が速い。

## 直したいときの言い方

1回のお願いで1か所だけ直す。まとめて頼むと他が崩れる。

```
7枚目だけ直してください。他のスライド・CSSは一切変更しないでください。
・右側の図をひとまわり小さく
・見出しを2行から1行に
・それ以外は現状維持。修正後の該当スライドのHTMLのみ出力
```

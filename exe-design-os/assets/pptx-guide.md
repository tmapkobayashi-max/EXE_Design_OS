## 0. なぜこの方式か（30秒で）

| | Canva AI | コード生成（Codex × python-pptx） |
|---|---|---|
| 色・フォント | 参考程度（ソフト） | **HEX/pt で厳密固定（ハード）** |
| 座標・余白 | 崩れやすい | **右から○cm・下から○cm を数値で完全再現** |
| 部分修正 | 全体を作り直しがち | **該当箇所だけ差分修正** |
| 再現性 | 低い | 高い（同じコード＝同じ結果） |
| 編集 | Canva内のみ | **PowerPointで誰でも再編集可** |

要点：**AIにデザインを"考えさせない"。トークン（下記）を渡し"組み立て"だけさせる。**

## 2. 精密ポジション指定（★ノンブル等の「右から/下から」★）

### 2-1. 単位の早見表

| 単位 | 換算 | python-pptx |
|---|---|---|
| 1 cm | = 360000 EMU = 約 37.8 px(96dpi) | `Cm(1)` |
| 1 inch | = 914400 EMU = 96 px | `Inches(1)` |
| 1 px(96dpi) | = 9525 EMU ≒ 0.0265 cm | `Emu(9525)` |
| フォント | pt | `Pt(12)` |

### 2-2. 「右から X・下から Y」を厳密に置く関数

python-pptx は**左上原点**。右下基準で置くには次式（要素幅W・高さH）：

```python
left = prs.slide_width  - X - W   # 右端から X
top  = prs.slide_height - Y - H   # 下端から Y
```

```python
from pptx.util import Cm, Pt, Emu
from pptx.enum.text import PP_ALIGN, MSO_ANCHOR

def add_page_number(slide, prs, number,
                    from_right=Cm(0.9), from_bottom=Cm(0.5),
                    box_w=Cm(1.6), box_h=Cm(0.6)):
    """数字を右下に、右端/下端からの距離で厳密配置。右揃え・下揃え。"""
    left = prs.slide_width  - from_right  - box_w
    top  = prs.slide_height - from_bottom - box_h
    tb = slide.shapes.add_textbox(left, top, box_w, box_h)
    tf = tb.text_frame
    tf.margin_left = tf.margin_right = 0          # 内側余白ゼロ＝数値どおり
    tf.margin_top  = tf.margin_bottom = 0
    tf.vertical_anchor = MSO_ANCHOR.BOTTOM
    p = tf.paragraphs[0]; p.alignment = PP_ALIGN.RIGHT
    r = p.add_run(); r.text = str(number)
    r.font.name = "Meiryo"; r.font.size = Pt(11)
    r.font.color.rgb = RGBColor(0x37,0x37,0x37)
```

### 2-3. ノンブル運用ルール（テンプレ実測 & ご要望反映）

- **1ページ目（表紙）は付けない**。2ページ目から採番（テンプレも `showSpecialPlsOnTitleSld=0` で設定済み）。
  → コード側では「2枚目以降のみ `add_page_number` を呼ぶ／番号を `i` で 2 から振る」。
- **テンプレ実測の既定位置**：数字ボックス＝右端から約 **0.44 cm**・下端から約 **0.02 cm**（ほぼ下端フラッシュ）、右揃え。
- **推奨（見栄え）**：右から **0.9 cm**・下から **0.5 cm** に少し浮かせる（上コードの既定値）。
- 変えたい時はプロンプトで「右から◯cm・下から◯cm」と数値指定するだけ。px希望なら `Emu(px*9525)`。

> 例：「ノンブルを **右から1.2cm・下から0.7cm**、Meiryo 10pt、色#373737、右揃えで。表紙は付けない」

## 3. スライドの型（テンプレ）

型番号で指示すると崩れにくい。
- **T-01 表紙**：ノンブル無し／タイトル大＋サブ＋日付・ロゴ
- **T-02 章扉**：紺 or 青背景、章番号＋章タイトル、余白広め
- **T-03 本文（箇条書き）**：小見出し＋3〜5点、1点1行・名詞止め
- **T-04 2カラム**：左テキスト／右図・数値、重心を揃える
- **T-05 比較表**：ヘッダ行=紺、ゼブラ=#E2F1FA、差し色は結論セルのみ
- **T-06 数値ハイライト**：大きな数字（青/珊瑚）＋補足小文字
- **T-07 まとめ／CTA**：結論1文＋次アクション＋連絡先・ロゴ

共通：1スライド1メッセージ／情報は上→下・左→右／詰め込みすぎない。

## 5. 修正プロンプトの型（部分修正の最大のコツ）

**❌**「なんかしっくりこないので直して」
**⭕（1回1変更）**：
```
3枚目（T-05 比較表）だけ修正。他のスライド・関数は一切変更しない。
- 結論セルの色を 珊瑚(#FF6366) → 青(#0071BC) に。
- ヘッダ行の文字を Bold のまま 20pt に。
- ノンブルは右から1.0cm・下から0.6cmに変更。
- それ以外は現状維持。修正後の該当関数のみ出力。
```

原則：①対象を1スライド(1関数)に限定と明言 ②変更点を数値で具体化(色=HEX/寸法=cm/pt)
③「他は変更しない」を毎回書く ④「該当箇所のみ出力」で全体再生成を防ぐ

## 8. 画像生成フロー（Codex運用ガイド）

> 役割分担（社長方針・2026-07-21確定）：**Claude＝デザイン・文章の組み立て（第1〜7章、python-pptx）／Codex＝画像生成のみ**。
> 理由：python-pptxで組み立てるAIは写真・イラストのような画像そのものを作るのは不得手なので、画像生成は分業する。
> 依頼先はCodex（松浦さんが契約している有料版・ChatGPT上のDALL-E呼び出し機能）に統一する。
>
> **経緯（無料Geminiを見送った理由）**：当初Gemini（無料版）で試したところ、
> ①「文字を入れない」という指示を守らず日本語文字が写り込む、②1日の無料生成上限に達すると
> 画像を作らず"作ったふうの説明文"だけを返す、③Google AI Studioの画像対応モデルは無料では使えず
> 有料API課金かサブスクが必要、という制約が続けて発生した。松浦さんが既にCodexを有料契約しているため、
> 無料枠に振り回されるGeminiではなくCodexに一本化することにした。
>
> 注意：ここでの「Codex」は第1〜7章の"コード生成AI"としてのCodexとは別の使い方（ChatGPT上でのDALL-E画像生成機能）を指す。
> 同じ製品でも「コードを書かせる」用途と「画像を作らせる」用途があると理解しておく。

### 8-1. 全体フロー

```
① 内容を決める（第1〜7章の要領で章立て・骨子を先に固める）
② 骨子の中で「画像が要る箇所」を洗い出し、8-2の型で「画像ブリーフ」を作る
③ 画像ブリーフの1項目＝1画像として、8-3のプロンプト型でCodex（ChatGPT）に依頼（1画像=1チャットが安定）
   ※Codexは自動でDALL-E相当の画像生成ツールを呼び出す。JSON等を手書きする必要はなく、自然文で頼むだけでよい。
④ 生成されたPNGをダウンロードし、sozai/ に分かりやすい名前で保存
⑤ Claudeにブリーフのファイル名を伝え、pptxの座標指定で組み込んでもらう
⑥ PowerPointで確認。ズレがあれば「修正プロンプトの型」（第5章）と同じ要領で座標だけ直す
```

### 8-2. 画像ブリーフの型（★案件ごとにこの表を埋める★）

| 項目 | 記入内容 |
|---|---|
| 対象スライド | 例：7枚目「画面ではどう見える？」 |
| 内容 | 何を描くか（被写体・構図・シーン） |
| スタイル | 線画/フラット/実写風/3DCG風 など |
| 配色 | 本ガイド1-1のHEXトークンを指定（近い色で代用しない） |
| 背景 | 透過が必要か／実写背景でよいか |
| 比率 | 16:9・1:1・4:3 など、配置予定サイズに合わせる |
| 文字・ロゴ | 「入れない」を基本にする（テキストはpptx側で別途重ねる） |
| 保存ファイル名 | 例：`icon_shiru.png`（後で機械的に組み込めるよう命名規則を決めておく） |

優先度（A=必須級／B=余裕があれば）を付けて並べると、Codex依頼の順番が決めやすい。

### 8-3. Codex（DALL-E）プロンプトの型（★コピペ用マスター★）

```
[被写体]のイメージを1枚作ってください。
・[構図・シーンの説明]
・スタイルは[線画/フラット/実写風/3DCG風など]
・配色は [HEXコード] を基調（近い色での代用は不可）
・背景は[透過／実写背景など]
・アスペクト比は[16:9／1:1／4:3など]

【厳守・NG要素】
・文字、数字、単語、ロゴ、アイコン、記号は画像内に一切描かない
・グラフ、チャート、データパネル、ダッシュボード風の要素は一切描かない
・看板、タグ、プレート、モニター画面のような矩形パネルも描かない
```

修正したい時はそのまま会話で続ける（例：「もっとシンプルに」「配色を珊瑚色寄りに」「文字が入ってしまったので消して」）。
1チャット1画像に絞ると、意図しない要素が混ざりにくい。「文字を入れない」は禁止事項を具体的に列挙するほど守られやすい。

### 8-4. Do / Don't（画像編）

**Do**：ブリーフを埋めてから依頼する／HEXで配色を明示する／1回のチャットで1画像に絞る／
NG要素（文字・グラフ・パネル等）を具体的に列挙する／届いたPNGはそのままの解像度でsozai/に格納する

**Don't**：「いい感じの画像を」など曖昧な依頼／1チャットで複数画像を一気に頼む／
文字・ロゴ入りで生成させる（pptx側の文字と二重になり調整不能になる）／
配色をCodexの提案任せにする（ブランドトークンから外れる）／無料枠のGeminiに頼る（上限に達すると
画像を作らず説明文だけを返す不具合が出るため非推奨）
